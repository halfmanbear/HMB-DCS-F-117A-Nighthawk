# F-117 Layout Studio

Double-click `tools/launch_layout_editor.bat`, or run from the mod folder:

```powershell
python tools/layout_editor.py
```

Requires Python 3.10+ with Tkinter, lupa and Pillow. These are already available
on the development machine. For another machine:

```powershell
python -m pip install -r tools/layout_editor_requirements.txt
```

## Working on a layout

1. Choose **HUD**, **MFD** (centre IRADS), **Left MFD**, or **Right MFD**. The editor executes the actual page and the mod's
   real drawing helpers. Nothing is saved just by opening or previewing it.
2. Click a symbol. The inspector identifies its source line, parent and parameters;
   the source pane scrolls to the corresponding code.
3. Drag a symbol to adjust its source x/y position. The selection box follows the
   drag; the display rebuilds on release. Use **Select parent / move a group**
   to move a container, then drag within the selection box. Snap is in local
   display units; set it to zero for continuous movement.
4. Positions generated by one loop/shared source call move together. Expressions
   are preserved with an added offset. Shapes without an x/y source pair, such as
   MFD crosshair lines defined entirely by vertices, are edited in the source pane.
5. Edit dimensions, vertices, text or constants directly in the source pane.
   **Preview source** / **Ctrl+Enter** reruns Lua. Syntax errors retain the last
   successful preview and show the error in the status line.
6. **Save Lua** / **Ctrl+S** saves only the currently selected page. An exact copy
   of the previous file is placed in `tools/layout_editor_backups/<timestamp>/`.
   Saving refuses to overwrite a file changed externally since it was loaded.
7. **Reload** reads external edits. **Undo** reverses previewed source edits and
   drags; the source pane also has its own normal text undo behavior.

Use the mouse wheel to zoom and middle-drag to pan. **Centre view / reset zoom**
restores the starting view. **Export PNG** exports the current preview without
the selection box.

## Visibility and flight conditions

The parameter list shows every parameter referenced by the current page.
Filter by name, select one, enter a value and press Enter or **Set parameter**.
Values can be numbers or strings. Unspecified values default to zero. Parameters
are independent sample inputs, rather than an offline simulation of HUD_Device
or Displays.lua. For example, changing airspeed does not automatically calculate
Mach, flight phases or approach mode; set the relevant parameters too.

Useful examples:

- `ROLL_HUD`, `PITCH_HUD`: radians, so approximately `0.174533` is 10 degrees.
- `VELVEC_HUD_X`, `VELVEC_HUD_Y`: velocity-vector offsets.
- `HEADING_HUD`: degrees; `CURR_IAS`: knots; `ALTITUDE_HUD`: feet.
- `altTape` drives the old altitude tape independently of `ALTITUDE_HUD`.
- `VVI_HUD` drives the numeric VVI; `VVI_SCALE` drives its pointer.
- `F117_IRADS_LOCK_VALID`: 0 for search, 1 for tracking.
- `IRADS_ZOOM`: 1 / 2 / 3 for WIDE / MED / NAR.
- `F117_LASER_ARMED` and `F117_LASER_FIRING`: 0 / 1.

**Show all modes / hidden symbols** bypasses controller visibility and opacity
to help find hidden elements. Mutually exclusive labels will overlap in this mode.

## Reference overlay

Use **Reference image** to load a PNG/JPEG crop containing just the HUD or MFD
diagram, then adjust reference opacity. The image stretches to the square preview;
crop the reference to a square with appropriate margins before importing it.
The reference is a drawing aid and does not alter saved Lua.

## Measured cockpit boundaries

The three MFD previews have an optional amber boundary measured from the live
cockpit blend, including rounded corners and connector offsets. Outside the
physical screen guide is dimmed. **Guide units / metre** controls its provisional
mapping to Lua coordinates; confirm this scale in DCS before relying on it as
an exact rendering boundary.

The HUD now uses a shared angular working profile: **20 x 15 degrees**, centred
at **{0, -50} milliradians** relative to the connector reference. The accepted
profile is in `Cockpit/Scripts/HUD/Indicator/layout_profile.lua`, also used by the
in-game calibration page. It records the centred design area from the accepted
head-movement tests; it does not establish aircraft boresight or pitch accuracy.
The accepted [centred capture](assets/hud-centred-calibration-2026-10-29.png) is
preserved alongside the profile documentation.

The operational HUD source still uses FOV units. Reload the aircraft once after
this update: `HUD_def.lua` records its actual FOV and milliradian scales in the
normal `Saved Games/DCS/Logs/dcs.log`. Studio reads their ratio automatically,
converts the working rectangle into the existing Lua source coordinates and
shows the X/Y limits. It does not infer this ratio from the old pitch gain.
Open Studio after the reload, or click **Centre view / reset zoom** in an already
open editor. The view fits the accepted working rectangle with margins. Without
the log entry, Studio explicitly says the boundary is pending and draws no
invented HUD bounds. **Guide units / metre** applies to MFDs only.

For HUD preview, **Approximate stencil clipping** clips against this working
rectangle and retains the internal tape masks. The finite-depth glass meshes are
excluded from the offline stencil simulation. Turn clipping off to find symbols
outside the working area, then move them using their normal source coordinates.
The amber border is the centred layout guide; the real head-dependent aperture
remains the in-game physical mask and can reveal less of that area at other
viewpoints. No offline screenshot can represent every VR head position.

Use **View measured glass / screen shapes** for physical dimensions of all three
displays and both HUD panes. See [the measurement report](cockpit-display-measurements.md)
and [calibration instructions](display-calibration.md) for the physical mask.

## Accuracy limits

This is a layout workbench, not DCS's rendering engine. It supports parent
transforms, planar rotation, line/mesh geometry, texture atlas UV mapping,
parameter text, common visibility/movement controllers and approximate stencil
clipping. Unsupported controllers are reported in the status line. Missing
texture files appear as grey outlines.

Text uses a desktop monospace font with approximate metrics, not the DCS font
atlas. Thick line joins, blending, stencil behavior, 3D `init_rot` components,
collimation, combiner optics and the pilot's eye position may differ. The MFD
camera image and flight/device systems are not simulated. Check final font sizes,
clipping and optical alignment in DCS before considering a layout finished.

The original `hud_preview.py` is kept as a separate older tool.

## Left and right display status

The left colour VSD and right basic HSD are registered as the default in-game
side displays. See [VSD design notes](left-vsd-design.md) and
[HSD design notes](right-hsd-design.md) for live data and remaining limitations.
Both are editable in Layout Studio, within the measured screen boundaries.
Their calibration overlays are disabled; HUD and centre calibration remain enabled.
Reload the aircraft/mission after saving to see changes in DCS.

The VSD uses `MFD-PLASHKA-CENTER1 / DOWN1 / RIGHT1`; the HSD uses
`RADAR-PLASHKA-CENTER / DOWN / RIGHT`. Those connector frames were calibrated
against the cockpit model. The old alignment starter files are preserved separately.

You can render a starter without opening the editor:

```powershell
python tools/layout_editor.py --render "Left MFD" --output tmp/left-mfd.png
python tools/layout_editor.py --render "Right MFD" --output tmp/right-mfd.png
```

## Automated renders and checks

```powershell
python tools/layout_editor.py --render HUD --output tmp/hud.png
python tools/layout_editor.py --render MFD --output tmp/mfd.png
python tools/layout_editor.py --render MFD --params my-sample-values.json --output tmp/mfd-track.png
python -m unittest discover -s tests -p test_layout_editor.py
```

The optional JSON file is a flat object of parameter names and values.

## OCIP HUD page

The active HUD now uses the [basic OCIP layout](hud-ocip-design.md). It converts
angular drawing coordinates using DCS scales, and the preview uses the logged
conversion. Use the `F117_OCIP_*` preview parameters for the new flight readouts
and validity gates; the side MFDs retain their existing parameters. HUD calibration
is disabled so the production HUD is visible without the cyan ruler.

## Native stroke display port

Operational pages now use native vector stroke fonts/lines. The editor previews the mod-owned glyph source and preserves the same source coordinates when dragging. MFD sources are now baked by the separate F117Displays.dll adapter, with readiness-gated holders configured in render_config.lua/LCD. The editor continues editing the source layouts; it does not emulate the compositor. Live IRADS video appears as an empty backdrop offline. See display-readability.md for rendering and validation details.
